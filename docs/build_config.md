# Build Configuration Guide

## 1. Build System Overview

Atlas uses **Bazel 6.5.0** (`.bazelversion`) as its build system. The build
configuration is organized across three layered files to separate project-wide
defaults from machine-local platform detection.

### 1.1 Bazel Entry Points

| Command | Purpose |
|---------|---------|
| `bazel build //...` | Build everything for the host platform |
| `bazel test //...` | Run all test suites |
| `bazel build //src/public:atlas` | Build the public shared library only |

### 1.2 Platform Targets

Atlas defines six platform targets (see `platforms/BUILD`):

| Config alias | Platform target | Use case |
|-------------|----------------|----------|
| `--config=macos_arm64` | `//platforms:macos_arm64_platform` | macOS Apple Silicon |
| `--config=macos_x86_64` | `//platforms:macos_x86_64_platform` | macOS Intel |
| `--config=linux_x86_64` | `//platforms:linux_x86_64_platform` | Linux x86-64 |
| `--config=linux_aarch64` | `//platforms:linux_aarch64_platform` | Linux AArch64 (edge devices) |
| `--config=android_arm64` | `//platforms:android_arm64_platform` | Android arm64-v8a |
| `--config=android_x86_64` | `//platforms:android_x86_64_platform` | Android x86_64 |

The host platform is auto-detected by Bazel via `--enable_platform_specific_config`
(in `.bazelrc`), which maps `macos` / `linux` constraints to the corresponding
`--cxxopt=-std=c++17` flags automatically.

## 2. Configuration File Layering

```
.bazelrc                 # Project-wide, committed (shared config, aliases,
                          #   try-import directives)
    try-import .configure.bazelrc   # Auto-generated by CI/setup (optional)
    try-import .user.bazelrc        # Machine-local, generated by platform_setup.sh
```

### 2.1 `.bazelrc` (committed)

Contains project-wide settings:
- C++ standard (`--cxxopt=-std=c++17`)
- Platform config aliases (`--config=macos_arm64`, etc.)
- Android cross-compilation flags (`--incompatible_enable_cc_toolchain_resolution`)
- `try-import` for local overrides

### 2.2 `.configure.bazelrc` (optional, git-ignored)

Intended for auto-generated settings produced by CI scripts or one-time
setup tools. Currently unused — reserved for future automation.

### 2.3 `.user.bazelrc` (machine-local, git-ignored)

Written by `tools/platform_setup.sh` after detecting platform-specific
paths (Android SDK/NDK, SNPE SDK). Runtime settings:

```
build --repo_env=ANDROID_HOME=/path/to/sdk
build --repo_env=ANDROID_NDK_HOME=/path/to/ndk
build:android --action_env=ANDROID_HOME=/path/to/sdk
build:android --action_env=ANDROID_NDK_HOME=/path/to/ndk
build --repo_env=SNPE_SDK_PATH=/path/to/snpe
```

These `--repo_env` flags feed the `WORKSPACE`-level repository rules
(`android_ndk_repository`, `snpe_sdk_repo`).

## 3. Platform Auto-Detection Script

### 3.1 `tools/platform_setup.sh`

Detects local Android SDK/NDK and SNPE SDK installations, then writes
`.user.bazelrc` with the discovered paths. Run once after cloning.

### 3.2 Usage

```bash
./tools/platform_setup.sh          # verbose mode (default)
./tools/platform_setup.sh --quiet  # silent; errors only
```

### 3.3 Detection Logic

**Android SDK / NDK** (reuses logic from the upstream Bazel Android setup):

1. Check `$ANDROID_HOME` environment variable.
2. Scan candidate paths:
   - `$HOME/Library/Android/sdk` (macOS)
   - `/opt/local/usr/android/sdk`, `/opt/local/usr/android` (Linux Docker)
3. Validate by looking for the `platforms/` subdirectory.
4. For NDK: scan `$ANDROID_SDK/ndk/` and standalone candidate paths.
5. Parse `source.properties` to get the major version; require **r27+**.
6. On macOS prefer NDK r28.

**SNPE SDK** (optional backend):

1. Check `$SNPE_SDK_PATH` environment variable.
2. Fall back to known paths: `/opt/qualcomm/snpe`, `/opt/qcom/snpe`.
3. If found, emit `build --repo_env=SNPE_SDK_PATH=<path>`.
4. If not found, the SNPE backend compiles as a stub (no error).

### 3.4 Output Example

```
  Android SDK: /Users/me/Library/Android/sdk
  Android NDK: /Users/me/Library/Android/sdk/ndk/28.2.13676358
  (SNPE SDK not found — snpe backend will compile as stub)
  Platform:    macOS arm64 (Apple Silicon)
  Config:      bazel build //... --config=macos_arm64

Wrote /path/to/atlas/.user.bazelrc
```

## 4. Android Cross-Compilation

### 4.1 Prerequisites

- **NDK r27+** (required by `rules_android_ndk`)
- Run `tools/platform_setup.sh` or manually set:

```bash
export ANDROID_NDK_HOME=/path/to/android-ndk-r27
```

### 4.2 Toolchain Registration

The NDK toolchain is declared in `WORKSPACE`:

```python
android_ndk_repository(
    name = "androidndk",
    api_level = 24,
)
```

It reads `$ANDROID_NDK_HOME` from `--repo_env` (set in `.user.bazelrc`
by `platform_setup.sh`).

### 4.3 Build Commands

```bash
# arm64-v8a
bazel build //... --config=android_arm64

# x86_64 (emulator)
bazel build //... --config=android_x86_64
```

## 5. SNPE Backend (Optional)

### 5.1 Prerequisites

- Qualcomm SNPE SDK installed on the host.
- The SDK path may be provided via:
  - `$SNPE_SDK_PATH` environment variable, or
  - detected by `tools/platform_setup.sh`.

### 5.2 Repository Rule

The `snpe_sdk_repo` repository rule (`third_party/snpe/snpe_repo.bzl`)
creates `@snpe_sdk` from the local SDK installation. It is triggered
by `atlas_setup()` in `WORKSPACE` when `snpe_major` is provided.

### 5.3 Stub Behavior

When no SNPE SDK is available, `@snpe_sdk` is created as an empty
repository with `SNPE_MAJOR = None`. The SNPE backend sources
(`src/backend/snpe/`) compile as a stub, returning
`ErrorCode::kBackendNotFound` at runtime.

## 6. Build Command Quick Reference

| Scenario | Command |
|----------|---------|
| Build everything (host) | `bazel build //...` |
| Run all tests | `bazel test //...` |
| Build public shared lib | `bazel build //src/public:atlas` |
| Build for Android arm64 | `bazel build //... --config=android_arm64` |
| Build for Android x86_64 | `bazel build //... --config=android_x86_64` |
| Build for macOS arm64 | `bazel build //... --config=macos_arm64` |
| Build for Linux x86_64 | `bazel build //... --config=linux_x86_64` |
| Build for Linux AArch64 | `bazel build //... --config=linux_aarch64` |
| Install lib + headers | `./tools/install_atlas.sh <prefix>` |
| Regenerate `.user.bazelrc` | `./tools/platform_setup.sh` |

## 7. Troubleshooting

### 7.1 Android build fails with "NDK not found"

- Run `./tools/platform_setup.sh` to auto-detect the NDK path.
- Verify the detected NDK version >= r27: check `source.properties` in the
  NDK root directory.
- Fallback: set `ANDROID_NDK_HOME` manually and re-run the script.

### 7.2 Android build fails with "no toolchain found"

Ensure `--config=android_arm64` or `--config=android_x86_64` is passed.
The `--incompatible_enable_cc_toolchain_resolution` flag must be active
(it is included in `--config=android`).

### 7.3 Bazel reports "build --repo_env" is unknown

Update Bazel to 6.x or later. `--repo_env` is available since Bazel 5.x.
This project requires Bazel 6.5.0 (see `.bazelversion`).

### 7.4 ONNX Runtime library not linked

ONNX Runtime prebuilt binaries are fetched via `http_archive` in
`atlas_deps.bzl`. Verify network connectivity. If behind a proxy,
configure `http_archive` URLs with a mirror or add `--host_javabase`
options for proxy settings.
